# CLAUDE.md

A low-N benchmark for antibody property prediction: frozen ESM-2 embeddings vs.
cheap Biopython descriptors, across training-set sizes, on two public
developability datasets. Read `README.md` first — it is the write-up, not a
summary, and it states every finding the code is expected to support.

## What this project is actually for

The deliverable is a **credible negative result**: frozen protein-language-model
embeddings do not beat hand-computed descriptors in the low-N regime. A negative
result is only worth anything if the methodology is airtight, so the priority
order here is unusual:

1. **Honesty of the protocol** beats headline numbers.
2. **Headline numbers** beat code elegance.
3. Code elegance last.

Concretely: if you find a bug that makes the benchmark look *worse* or less
conclusive, that is a good find and should be reported plainly, not softened. If
you are tempted to change a default that would improve a score, don't — say what
you found and let the user decide.

## Commands

```bash
make test        # 156 tests, ~7s, no data or GPU needed. Run this first.
make setup       # .venv + requirements + test requirements
make data        # TDC downloads, cluster and leakage summaries
make embed       # frozen ESM-2 650M forward pass, cached (~4 min M-series)
make quick       # 3-seed sanity sweep (~2 min)
make run         # the full 23,040-fit sweep (~40-60 min on 12 cores)
make figures     # every table and figure in the README
```

`make test` needs none of the downloads — that is deliberate, see below. Always
run it before and after touching anything in `src/lown/`.

## Layout

```
src/lown/config.py      paths and the experiment grid; everything agrees on this
src/lown/data.py        TDC loaders (regex chain parsing, the two datasets differ)
src/lown/features.py    aac / biophys / cdr blocks, and `cheap` = all three
src/lown/embeddings.py  frozen ESM-2, cached by unique chain sequence
src/lown/splits.py      identity clustering and random vs. cluster-held-out splits
src/lown/heads.py       linear / mlp / gbm behind a StandardScaler, plus metrics
src/lown/experiment.py  the nested-subsample sweep
src/lown/scaling.py     saturating power-law fit and "how many more antibodies?"
src/lown/plots.py       every figure
scripts/                one numbered script per phase
tests/                  invariant tests; see tests/README.md
results/                committed. The README's numbers are read off these.
figures/                committed, so the README renders without a run.
```

`data/` is gitignored and regenerated by `make data embed`.

## Invariants — do not break these

These are the load-bearing methodological claims. Each is asserted by the test
suite; if a change makes one fail, the change is wrong until proven otherwise.

- **Cluster-held-out splits leak nothing.** Zero test antibodies may have a
  ≥80%-identity neighbour in training. Clustering is single-linkage over the
  *union* of two rules (Fv ≥90% **or** concatenated CDR3 ≥80%), deliberately
  conservative. Do not "tidy" it down to one criterion — clustering the whole Fv
  at 80% collapses 1,173 of 2,409 SAbDab antibodies into a single cluster,
  because antibody frameworks are conserved by construction.
- **Subsamples are nested.** For a given seed, the N=25 training set is a prefix
  of the N=50 set. Independent draws at each N would make curves unpaired and
  the one-sigma bands an overstatement.
- **The test set is fixed per seed** and never subsampled, so every point on a
  curve is scored on exactly the same antibodies.
- **Every feature set and head sees the same rows within a seed.** This is what
  licenses the paired Wilcoxon tests. Comparing best-of-head envelopes across
  feature sets instead would smuggle in a selection effect — the README says so
  explicitly.
- **Nothing from the test set reaches a fit.** Every head is a pipeline with the
  `StandardScaler` inside it. Never scale before splitting.
- **The `random` feature set is the floor.** Gaussian noise must not beat an
  informative feature set in any group. If it does, something is manufacturing
  skill.

## Conventions

- **Comments explain *why*, at length, and often defend a choice.** This is a
  benchmark whose credibility is the product, so the code argues for its own
  decisions — see the module docstrings in `splits.py` and `scaling.py` for the
  register. Match it. Do not strip these down.
- **British spelling** in prose and comments (`normalise`, `behaviour`,
  `licence`).
- Config constants live in `config.py` so the runner, plots and notebook agree.
- A pathological cell must never kill an hour-long sweep: `_one_cell` catches
  per-fit exceptions and records a `degenerate` row. Keep that.
- Degenerate regression scores are `0.0`, not `NaN` — NaNs would silently drop
  cells from the aggregated means and bias them upward.

## Tests

Read `tests/README.md` before adding tests. Two things to know:

- The suite is **offline and has no `torch`, `transformers` or `PyTDC`**
  (`requirements-test.txt` is a deliberate subset). Keep it that way — the point
  is to verify the methodology in seconds without a model download. Tests that
  genuinely need the real panels use the `real_chen` fixture and skip when
  `data/raw` is empty.
- Fixtures **synthesise** antibody panels (`conftest.py`). `clonal` is twelve
  five-member families, the structure that breaks a random split; `distinct` is
  the TAP-like no-near-duplicates regime.

`test_results.py` pins the README's numbers to the committed tables. If you
re-run the sweep and a number moves, update the prose *and* the test together,
and say in the commit message which claim changed.

## Known sharp edges

- **`cdr_h3` is offset by one residue.** `_CDRH3` allows one to three residues
  after the framework-3 cysteine but the quantifier is lazy, so it takes exactly
  one and the captured loop keeps it. Every reported CDR-H3 length is one longer
  than the canonical definition. Documented in the README; pinned by a test.
- **Failed CDR extraction over-merges clusters.** `rapidfuzz.fuzz.ratio("", "")`
  is 100, so antibodies where both CDR3 regexes fail share an empty
  representation and land in one cluster (15 of 2,409 in SAbDab). The direction
  is safe — over-merging costs test-set size and can never create leakage — and
  a test fails if it ever flips.
- **`_resolve_grid` may not emit an `"all"` label.** When the training pool size
  coincides exactly with a requested size, that size wins the label. Aggregate
  on the realised `n_train`, never on the presence of an `"all"` row.
- **`config.py` creates directories on import.** Importing `lown` anywhere makes
  empty `data/`, `results/` and `figures/` appear.
